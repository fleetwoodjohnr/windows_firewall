# Windows 11 acceptance checks

Record Windows edition/build, app version and results. Use a disposable Windows 11 x64 VM with a snapshot for firewall, hardening, reboot and uninstall checks. Test Home and Pro where available; some features require Pro or compatible hardware. Keep console access. Passing portable tests does not establish these results.

## Installation and runtime

1. Build with `scripts\bootstrap.ps1` from an elevated Windows PowerShell 5.1 terminal. Confirm download verification, pytest, frozen self-tests and Inno Setup all succeed. A build must stop if a checksum, publisher signature, dependency scan or test fails. Do not bypass a failed scan.
2. Install on a clean Windows 11 x64 VM without Python or Qt. Decline optional extras for the first run. Confirm all seven pages open without import errors or a UAC prompt just to read status. Standard users may see permissions-related gaps in system status; those must be labelled unavailable.
3. Run `scripts\verify-windows.ps1 -RunScan` from the installed directory in elevated Windows PowerShell. Review its JSON report on the Desktop. All checks must pass, including a harmless file scanned through the service. Run the app from a different working directory and at 100%, 150% and 200% display scaling.
4. Sign out and back in. Confirm one monitor in the notification area, opening the app again uses the same instance, and closing the window leaves monitoring active. Exit through the tray and confirm it stops. Confirm another Windows account has separate folders/history.
5. Check the `WinHardenScanner` service starts automatically as LocalSystem. Check `%ProgramData%\win-harden` permits standard users to read but not modify state; its scanner subdirectory must not allow standard users to read or modify its database. Application files under Program Files must not be writable by standard users.

## Application updates and upgrades

1. Build a prior-version installer locally to test upgrades: bump `win_harden/version.py` down one patch level on a scratch branch, run `scripts\bootstrap.ps1`, and keep that installer. No earlier release exists to download. Install it, save watched folders and preferences, and queue harmless scans. Then run the candidate installer. Confirm settings, histories and the original-settings journal survive and the displayed version and executable ProductVersion agree. Confirm only one installed application and scanner service remain.
2. On an updater-enabled build, use **Check for updates** against a newer published stable release. Confirm the displayed version and plain-text notes match GitHub, downloading begins only after **Update**, and the UI stays responsive. Confirm background checks run once daily and notify once per version; disabling automatic checks must still allow manual checks.
3. Cancel during download and disconnect the network during another download. No setup may launch. Verify the application and monitor remain usable. Check the same behaviour for corrupt/missing assets and rate limits using the automated updater tests; never publish intentionally broken production releases to test errors.
4. Cancel UAC, then cancel the wizard before replacement. The GUI must keep monitoring. Cancel on Preparing to Install after the old service has stopped: setup must restart it. With a security change in flight, the Update action must wait. With another account's tray process open, setup must ask for closure before replacing files. Reopen that account's monitor afterward.
5. Complete the upgrade with active scans. Confirm interrupted work is reported honestly, the scanner starts, one monitor opens in the initiating account, and the GUI is unelevated even when a different administrator supplied UAC credentials. Do not accept an upgrade that launches the GUI under the administrator's profile.
6. Run the same installer again to repair it, and verify a subsequently built older-version installer refuses a downgrade. Simulate service startup failure in a disposable VM: setup must report repair instructions and retain state. Confirm no reboot occurs without the user's choice.
7. After publishing the first release, install it manually and use **Check for updates**. The correct result is *No newer published version is available* — not *No application releases have been published yet*, which means the release is malformed or unparseable. Confirm the Updates page shows the installed version as latest and stamps a successful check.
8. Before releasing, confirm an invalid/mismatched tag fails validation and incomplete uploads remain drafts. Verify all public asset digests and ensure no runtime authentication token is present. Keep `windows-build-diagnostics` from any failed build.

## Scanning and recovery

1. Run quick, full, custom file, and folder scans. Confirm the window remains responsive; results must distinguish queued, scanning, no threats detected, remediated, action required, failed and incomplete. Inspect Defender events 1000/1001 for successful scans. Never accept a generic exit code as proof that a file is clean.
2. Download an ordinary vendor file through a browser into Downloads. Confirm its temporary `.crdownload`/`.part` file is deferred and the completed file appears in Recent scans. Modify it afterward and confirm a new scan. Repeat with Unicode, spaces, apostrophes, brackets and dollar signs in the path. Add a different local folder and repeat there.
3. Pause additional scans, download a file, resume, and confirm it is scanned. Exit the monitor, download another file, restart, and confirm reconciliation. Stop/restart the service while work is queued; custom files must be reauthorized. Restart while a scan is running; an interrupted result must not become clean.
4. In a disposable VM, use the **harmless EICAR antivirus test file** from [EICAR's official test page](https://www.eicar.org/download-anti-malware-testfile/) or [Microsoft's Defender demonstration](https://demo.wd.microsoft.com/). Do not use real malware. Keep Defender enabled and do not add exclusions. Browser or real-time blocking before the file reaches Downloads is a successful Defender interception: inspect Windows Security Protection History. If the file reaches the additional scanner, confirm it is flagged/remediated, and a notification appears. Never require a clean result for this test.
5. Review **Remove active threats**: confirmation must state that it remediates all active threats. Cancel UAC and verify no removal request is submitted. Quarantine review opens Windows Security. Do not restore the EICAR item to bypass detection.
6. Confirm unavailable/passive Defender, policy restrictions, inaccessible folders, reparse points, exclusions and interrupted scans produce explicit errors or incomplete results. Test offline definition updates; failure must be visible. Do not turn off protection on a production PC just to exercise these cases.
7. Confirm files can still be opened while a supplemental scan is pending; the monitor is not a download execution gate. Test unsupported/password-protected archives as coverage limitations, not as evidence of safety.

## Privilege, settings and uninstall

1. As a standard user, make a reversible change and approve UAC with an administrator account. Confirm the helper authenticates the original user and communicates successfully. Cancel a separate UAC request and confirm the selector does not report success. A failed/mismatched pipe connection must release the UI with an error.
2. In the VM, export baseline registry values, Defender preferences/ASR IDs, service startup/running state, optional features, firewall profiles, DNS addresses and DoH registrations. For each family, apply Basic -> Balanced -> Strict where supported, downgrade, then Off. Compare with the baseline, including absent values, NOTSET mitigations and absent ASR rules. Unsupported changes must explain the reason; partial failures must keep their restore records.
3. Apply two families sharing a setting, then revert in both orders. The remaining family must retain its setting; reverting the last claimant must restore the original. Repeat across broker restarts and Windows reboot.
4. With two network profiles active, change a shared firewall rule group and confirm the affected profiles match the confirmation. Check domain-managed rules report refusal when policy prevents a change. Test panic on/off from the VM console, verifying both actual traffic blocking and exact original-profile restoration.
5. Change DNS provider, switch provider, then select restoration/automatic. Check IPv4, IPv6 and DoH registrations; verify manually configured originals return. Test a removed/reconnected adapter and shared DoH registrations.
6. Reboot after LSA/Credential Guard changes and verify Windows still starts. Confirm BitLocker status never claims that a recovery key has been backed up. Existing firmware-locked policies can require manual recovery and must not be represented as automatically reversible.
7. Upgrade over the installed version with queued scans and a tray process present. Confirm one service and one monitor remain, files are updated, and state/history survive. Uninstall must stop/remove the service and sign-in entry, and restore journalled settings. Simulate a restore refusal in the VM: uninstall must stop before removing the app/journal. Direct user-selected settings and Defender quarantine may remain as documented.

Keep the verification JSON and any failure details. Broker diagnostics are under `%ProgramData%\win-harden\broker.log`; scan diagnostics are in the administrator-only `scanner\service.log`. Reports may contain local paths and machine configuration; review before sharing.
